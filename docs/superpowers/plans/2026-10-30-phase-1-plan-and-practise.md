# Phase 1 — Plan & Practise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new student signs up, completes onboarding, gets a starter plan, manages tasks and timed study sessions in a real planner, practises Prelims MCQs (build a set, take it, see results, review, mistakes, bookmarks), and an editor manages the question bank — all live on the Phase 0 demo stack on seeded sample data.

**Architecture:** Same modular monolith as Phase 0. New Postgres schemas `planner` and `practice` (own tables, FK only to `identity.users` and `catalog.syllabus_nodes`/`catalog.subjects`); two new tables in `identity` (preparation profile, study preferences). REST under `/api/v1`, every new endpoint behind `AuthGuard` and scoped to the caller's own rows. Time is server-authoritative (practice timers via `ends_at`, study sessions via heartbeats). No AI in this phase (rule-based starter plan; AI is Phase 3). Web pages are Next.js App Router pages that call the API through the existing `serverApi` (server components) and `apiFetch` (client components).

**Tech Stack:** unchanged from Phase 0 (Node 22, pnpm 9, NestJS 10, Drizzle + `drizzle-kit generate`, PGlite in tests, Jest + supertest, Next.js 15, Tailwind v4 tokens, Vitest + Testing Library) plus `zod@^3` in `apps/api` for request validation.

**Specs:** `docs/specs/02-auth-onboarding-profile.md` (§3–7, onboarding + settings), `08-prelims-practice.md` (practice + question bank; not mocks/All-India/AI), `10-planner-study-sessions.md` (tasks, sessions, goals, home; not AI plan/calendar), `18-admin-console.md` (question bank), `03-subscriptions-entitlements.md` (mechanism), `20-data-model.md`. Roadmap: `docs/specs/99-roadmap.md` §2 Phase 1. Decisions: `docs/specs/DECISIONS.md`. Phase 0 reference code: `apps/api/src/{identity,billing,catalog,admin,seed}`, `apps/web/src/{lib,components,app}`; leftovers and rulings: `docs/superpowers/phase-0-followups.md`, `phase-0-rulings.md`.

## Global Constraints
- **Run every command with Node 22:** `export PATH=$HOME/.local/node22/node_modules/node/bin:$HOME/.local/bin:$PATH`. API tests: `pnpm --filter @upsc/api test`; web tests: `pnpm --filter @upsc/web test`; typecheck: `pnpm --filter @upsc/api exec tsc --noEmit` and the same for `@upsc/web`.
- API prefix `/api/v1`; errors always `{"error":{"code","message",...}}` via `AppError`. Validation failures: HTTP 400, code `validation_failed`. Unknown or not-yours resource: HTTP 404 `not_found` (never 403, never leaking existence).
- Ids are UUIDv7 (`newId()`); timestamps `timestamptz` UTC; Postgres tables snake_case, Drizzle fields camelCase, as in Phase 0 schema files. Migrations are generated with `pnpm --filter @upsc/api db:generate`, committed, and must apply cleanly on PGlite (tests) and Postgres 18 (Neon). Never edit a generated migration after it has been applied anywhere; add a new one.
- **User isolation:** every query on user-owned rows filters by the caller's `user.id`. Each API task adds a test that user B cannot read, change or delete user A's row (expects 404).
- **Roles come only from `identity.users.roles`.** Admin/editor endpoints use `@UseGuards(AuthGuard, RolesGuard)` + `@Roles('admin','content_editor')` (RolesGuard is any-of). Student endpoints need no role.
- **Time zones:** "a day" means a calendar day in the user's `identity.users.timezone` (default `Asia/Kolkata`); day/week boundaries are computed server-side with that zone. Weeks start on Monday unless `study_preferences.weekStart = 'sunday'`.
- **Practice rules:** marking default GS Paper I = +2 correct / −0.66 wrong / 0 skipped, stored per session (`marking` jsonb) so it is configurable; `learning` mode never produces a score (accuracy only); timed default 72 s per question; correct answers, explanations and reasoning are **never sent to the client in `test` mode before submit**, and in `learning` mode only for a question after it is answered. Unverified PYQs are excluded from "PYQs only" sets (spec 08 FR-08-03 default). "How others answered" appears only when ≥ 100 first-attempt answers exist (constant `OTHERS_MIN_SAMPLE = 100`), otherwise "Not enough data yet".
- **Honesty about content:** all seeded questions are `verification_status = 'platform_sample'` and are labelled "Sample question" in the UI; no seeded question may be labelled a previous-year question. Exam-date countdowns use rows flagged `illustrative` and the UI says "Illustrative".
- **Entitlements:** add feature keys `planner.basic`, `study.session`, `practice.session`, `practice.pyq`, `practice.mistake_notebook` (enabled, unlimited on the free plan; real tiers are decision O1). Only `practice.session` (session create) and `study.session` (study start) are enforced with `@RequiresEntitlement`.
- **Out of scope for Phase 1** (do not build): AI plan/MCQ generation, mocks, All-India tests, weekly challenge, answer-key re-scoring and notifications, passages/map/chart/calculation question formats (only `single` and `statements`), recurring tasks, Google Calendar, notification/connected-tools/privacy settings pages, email verification flows, data export/deletion, public guest pages, progress/leaderboards (Phase 4), planner↔mentor/revision integrations. Pages for these stay stubs.
- Web: reuse Phase 0 tokens/components (`AppShell`, `StubPage`, `ErrorPanel`, Tailwind token classes such as `text-text`, `text-muted`, `bg-surface`, `border-border`, `rounded-card`, `rounded-control`, `bg-primary`). Every new page has loading-safe, empty, and error states; interactive controls are keyboard operable and labelled. Responsive down to 390 px.

## Review Focus
1. **Answer-key leakage:** in `test` mode, `GET /practice/sessions/:id` and `PUT …/answers/:ordinal` responses contain no `correctOption`, `explanation`, `optionReasoning` or `misconception` before submit; in `learning` mode only for already-answered questions (Task 8).
2. **Timer authority:** refreshing mid-test keeps the remaining time from the server; an answer after `ends_at` is rejected and the session auto-submits exactly once; submitting twice returns the same results and does not double-count mistakes (Task 8).
3. **Marking arithmetic:** all-skipped → score 0 and accuracy 0 (no `NaN`); 3 correct + 2 wrong in a 10-question set → 3×2 − 2×0.66 = 4.68; learning mode returns `score: null` (Task 8).
4. **One active study session per user** under two concurrent start requests (exactly one 201, one 409 `session_conflict`); idle heartbeats add no recorded time; a stale session (no heartbeat for 10 min) is offered for recovery instead of silently running (Task 4).
5. **Day boundaries in IST:** a task at 23:30 IST on the 14th appears in "today" for the 14th and not the 15th; week and month ranges use the same rule; a 00:10 IST task is not shown on the previous day (Tasks 3, 5).
